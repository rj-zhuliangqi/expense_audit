# 费用稽核平台能力与优势说明

## 1. 平台定位

该平台面向费用稽核、单据审核、票据核验等场景，整体能力拆分为数据准备、AI+规则 runtime、数据回写、全流程编排执行四个核心模块。通过把业务逻辑、执行逻辑和基础设施解耦，平台既可以支撑当前费用稽核场景，也可以较低成本复用到其他审核类业务。

平台的核心思路不是把所有能力堆在一个大流程里，而是把“准备数据”“执行判断”“回传结果”“串联流程”拆成独立能力层。这样既方便迭代单个模块，也方便后续复制到其他平台、其他业务线或其他行业场景。

## 2. 四大模块说明

### 2.1 数据准备模块

数据准备模块负责从上游系统、OCR 服务、主数据服务以及业务接口中拉取和聚合单据所需信息，并将原始数据整理为后续 runtime 可直接消费的标准化输入。

这一层的价值在于把分散、格式不一致、依赖多个外部接口的数据先做统一加工，减少后续规则和 AI 节点对上游系统的直接耦合。对于复杂业务来说，数据准备模块相当于平台的“标准化入口”，保证后续流程拿到的是结构一致、上下文完整的 preparedInput。

### 2.2 AI + 规则 Runtime 模块

AI + 规则 runtime 模块负责承接标准化输入，执行图驱动的规则逻辑，并结合 AI 节点完成业务判断。规则部分适合承载确定性校验逻辑，AI 部分适合处理复杂语义识别、非结构化内容判断或需要增强理解能力的场景。

这一层的意义在于把“确定性规则”与“智能判断能力”放在同一个执行框架里统一编排。一方面能够保证关键规则可控、可追踪，另一方面又能利用 AI 提升复杂场景下的识别和判断能力，兼顾稳定性与灵活性。

### 2.3 数据回写模块

数据回写模块负责将平台执行结果组装成上游系统可消费的数据结构，并将审核结果、日志、票据明细、OCR 结果等信息统一回传。

这使平台不仅能“算出结果”，还能把结果稳定地沉淀回业务系统，形成完整闭环。对于业务方而言，回写模块的价值在于减少人工二次整理，保证审核结论、明细信息、留痕数据能够统一进入后续业务流程。

### 2.4 全流程编排执行模块

全流程编排执行模块负责从队列中获取任务，驱动数据准备、runtime 执行和结果回写，并负责单据级与发票级任务的整体调度、汇总和异常处理。

这一层相当于平台的“总控中心”。它将业务编排逻辑集中管理，既可以处理队列消费、重试和多阶段执行，也可以控制整单和单票之间的关系，保证整条链路可运行、可扩展、可治理。

## 3. 核心优势

### 3.1 配套 UI 开发平台，业务配置效率高

平台的一个明显优势是可以结合 UI 开发平台，承载规则和 AI 组合的开发与维护。业务人员或实施人员可以围绕可视化界面组织规则节点、AI 节点和流程逻辑，而不必每次都直接改底层代码。

这样的能力可以显著降低需求响应成本。对于变化较快的业务场景，规则调整、审核口径变化、AI 节点替换都可以更快落地，减少研发反复介入的成本。

### 3.2 AI 与规则协同，兼顾稳定性与智能化

平台不是单纯依赖 AI，也不是只靠硬编码规则，而是把两者组合在统一 runtime 中。规则适合处理明确、稳定、必须可解释的判断逻辑，AI 适合处理复杂语义、非标准文本、图片识别结果理解等难以完全规则化的问题。

这种协同方式比单一路径更适合真实业务场景。它既保留了规则引擎的可控性，也补足了复杂场景下纯规则难以覆盖的能力边界。

### 3.3 复用能力强，可快速迁移到其他平台

平台已经将数据准备、runtime、回写、编排拆成独立模块，因此迁移到其他平台时，不需要整体推倒重来。通常只需要替换部分上游数据接口、调整规则图、适配新的回写结构，就可以复用原有主链路。

这意味着平台不仅适用于当前费用稽核场景，也适合迁移到合同审核、报销审核、票据核验、供应链单据校验等类似业务。对企业来说，这种复用能力可以显著缩短新场景落地周期。

### 3.4 模块边界清晰，便于扩展和维护

四大模块职责明确，每层只关注自己应该处理的问题。数据准备负责数据聚合，runtime 负责判断执行，回写模块负责结果输出，编排模块负责串联整个流程。

这种分层架构带来的好处是局部变更影响更小。后续无论是替换 OCR 厂商、替换上游接口、调整队列接入方式，还是新增新的结果落库方式，都可以在相应层面单独演进，而不需要牵一发而动全身。

### 3.5 图驱动执行逻辑，规则调整更灵活

平台的运行逻辑可以通过图配置进行组织，而不是完全写死在代码中。这样做的价值在于，业务流程和审核逻辑具备更强的可调整性。

对于经常变化的审核场景，这种图驱动方式能够降低规则变更门槛，提升平台对新业务、新口径和新流程的适配速度，也更适合长期演进。

### 3.6 天然支持异步化和队列化处理

平台具备面向队列消费的编排执行能力，能够从任务队列中拉取单据并进行异步处理。这样的设计天然适合处理批量任务、削峰填谷、与上游系统解耦等场景。

当业务量扩大时，队列化能力可以帮助平台更稳定地承接任务流量，同时让上游系统与审核执行链路保持松耦合关系。

### 3.7 容错和留痕能力更适合生产场景

平台在整单与单票处理之间保留了清晰边界，能够在复杂单据场景下进行结果汇总、错误记录和状态归一化。对于生产环境来说，这种能力有利于降低单点失败对整条链路的影响。

同时，平台还可以保留 preparedInput、OCR 原始上下文、执行结果和回写数据等关键留痕信息，方便后续审计、复盘、问题定位和结果追溯。

### 3.8 便于测试、联调和持续演进

由于模块之间边界清晰，平台比较容易进行单模块测试、联调测试和集成验证。无论是本地调试、队列联调，还是替换某个外部依赖做验证，都更容易定位问题和控制变更范围。

这对于持续演进非常重要。一个能够被稳定测试、稳定回放、稳定接入新能力的平台，才更适合长期作为中台能力沉淀下来。

## 4. 适用价值与推广方向

从业务价值看，这个平台适合沉淀为一类“审核执行中台”能力。凡是存在多源数据聚合、规则校验、AI 判断、结果回传闭环的流程，都可以复用这套模式。

从推广方向看，平台不仅可以服务当前费用稽核，也可以向更多审核和校验场景扩展，例如票据审核、单据合规校验、合同材料核验、供应链单证审核等。其核心不是绑定某一个业务，而是沉淀出一套可复用的审核执行框架。

## 5. 总结

这套平台的核心优势可以概括为四点：一是模块拆分清晰，便于治理和扩展；二是 AI 与规则结合，兼顾智能化与可控性；三是结合 UI 开发平台后，能够快速支撑业务配置和迭代；四是复用成本低，适合向更多平台和业务场景复制。

如果把它作为平台化能力持续建设，后续不仅能够服务当前项目，还可以逐步演进为企业内部统一的审核与稽核执行底座。
