- **核查基线**：`main` / `0b36655`

  - `差旅/差旅费-构建流程图稽核点 - Sheet1.csv`

## 1. 总体结论

**差旅费 32 个稽核点尚未全部完整实现。**

需要区分以下两个结论：

| 维度 | 当前结果 | 说明 |
|---|---:|---|
| 流程图节点挂载 | 32/32，100% | CSV 中的 32 条稽核点均已映射到流程图决策节点 |
| 业务规则闭环 | 未完成 | 多条规则依赖空的 `ruleStates`，缺少数据时会按 `PASS` 放行 |
| 差旅数据准备 | 部分完成 | 已标准化部分行程、交通、补助和发票字段，但仍有关键字段缺失 |
| W39 场景分类 | 未完成 | LLM 分类节点尚未配置，`invoiceScene` 默认为空 |
| 多发票去重 | 未确认完成 | `primaryInvoice`、`raisedRuleCodes` 只是预留接口，未发现完整更新闭环 |

因此，当前版本可以描述为：

> **32 个稽核点已经全部进入流程图，但不应认定为 32 个稽核点都已经完成真实业务稽核。**

## 5. W39 业务场景分类

第 30 条 W39 虽然已创建流程节点，但实际分类链路尚未接通：

- `travel_content_classification_llm` 节点仍为未配置状态；
- LLM 输出为空；
- 后处理读取 `ruleStates.w39_travel_scene` 或 `invoiceScene`；
- 数据准备层默认 `invoiceScene = None`；
- 未发现真实发票内容分类结果写回流程的逻辑。

因此 W39 当前不会稳定执行以下稽核要求：

> 判断发票内容是否属于城市间交通、市内交通、住宿、行李托运、退改签、疫苗检查、网络电话卡等差旅相关费用。

LLM 尚未配置时，应明确返回待分类或转人工审核状态，不应静默按通过处理。

## 6. 关键公共能力缺口

### 6.1 “仅报错一次”未形成完整闭环

流程图支持以下字段：

```text
primaryInvoice
raisedRuleCodes
```

但数据准备层默认值为：

```python
primaryInvoice = True
raisedRuleCodes = []
```

目前未发现多张发票执行过程中持续更新这两个字段的逻辑。因此，CSV 中标记“仅报错一次”的规则目前更像预留接口，不能确认已经实现跨发票去重。

### 6.2 sys-003、sys-004 没有稳定复用通用发票状态

差旅流程图中的发票作废和红冲规则主要依赖：

```text
ruleStates.sys003_void
ruleStates.sys004_red_flush
```

没有发现它们像通用流程一样直接根据 `verifyResult` 错误码完成判断。因此，即使 `verifyResult` 已表示发票作废或红冲，若上游没有额外写入 `ruleStates`，差旅流程仍可能返回 `PASS`。

### 6.3 差旅回写链路未实现

`expense_audit_orchestrator/profiles/travel/writeback.py` 当前存在两个占位函数：

- `travel_compliance_rule()`；
- `travel_audit_travels_builder()`。

二者都会直接抛出 `NotImplementedError`。因此差旅 profile 的完整执行链路仍未闭环：

```text
数据准备 → 流程图判断 → 合规判定 → auditTravels 回写
```

- 多发票“仅报错一次”；
- W39 真实分类结果；
- sys-003/sys-004 真实发票状态；
