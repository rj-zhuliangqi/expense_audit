## 5. 安全处理与多发票规则

### 5.1 接口失败

`TravelApiClient.fetch_all()` 对每个接口独立捕获异常，记录：

- `status=NOT_READY`；
- `blocking=True`；
- `severity=WARNING`；
- 接口路径和错误原因；
- 提示“无法完成对应稽核，需人工复核”。

流程图读取 `sourceStatus` 和 `ruleStates`，对相关规则输出 `WARNING`，不会将失败接口的空数组解释为“没有费用”。

### 5.2 W39

分类优先级为：

1. 禁止关键词：保险、餐饮、餐费、签证、快递 → `warning/forbidden`；
2. 差旅允许关键词：城市间交通、市内交通、住宿、行李、疫苗检查、网络电话卡、退改签等 → `pass`；
3. 未知内容 → `warning/unknown`；
4. 缺少内容 → `missing`。

流程图中的分类节点保留标准节点结构，但实现为确定性关键词分类，不依赖未配置的 LLM；后续如接入分类模型，只需替换分类节点，不改变 W39 输出契约。

### 5.3 多发票

- 第一张发票注入 `primaryInvoice=True`，后续发票注入 `False`；
- 所有发票先汇总税额，注入 `taxInfo.invoiceDeductibleTaxTotal`；
- 后续发票继承已命中的文档级规则代码/键；
- `raisedRuleKeys` 用于内部精确去重，避免 E32 代码复用影响逐票规则；
- 日期、旅客、座位、行李、W39 和月结火车票等逐票规则仍对每张发票执行。

## 6. 差旅回写实现

已注册以下 profile 回写函数：

- `travel_compliance_rule()`：对充值卡、保险等禁止内容返回不合规；
- `travel_audit_travels_builder()`：将 `travelSegments` 转换为 `auditTravels`；
- `travel_form_invoice_tax_views_builder()`：生成 `formInvoiceTaxViews`，支持多税率、发票金额、发票税额、可抵扣税额和发票信息主键。

当前输出字段为：

```json
{
  "miInstanceCode": "...",
  "invoiceNo": "...",
  "invoiceAmount": 0,
  "invoiceTaxAmount": 0,
  "invoiceDeductibleTax": 0,
  "taxRate": "...",
  "invoiceInfoId": "..."
}
```

飞书文档 revision 4 是查询接口文档，没有提供 `AuditTravel` / `FormInvoiceTaxView` 的回写样例。因此上述 DTO 字段已按现有通用回写契约和兼容别名实现，正式联调时仍需服务端确认 `invoiceInfoId`、`invoiceTaxAmount`、`invoiceDeductibleTax` 等字段是否需要改为 `aiid`、`taxAmount`、`deductibleTax` 或其他命名。
