# 差旅费接口能力核对报告

- **报告时间**：2026-08-07 17:40:59（Asia/Shanghai）
- **核对范围**：差旅费 32 个稽核点、差旅流程图 `graph-latest-travel-0807.json`、接口文档 `docs/费控AI应用-财务审批机器人-费用测调整.md`
- **目的**：记录差旅数据准备所需接口、字段覆盖、缺口和后续接口确认项，作为后续联调及版本核对基线。

## 1. 结论摘要

现有接口可以覆盖差旅稽核的大部分单据级数据，预计覆盖约 **80%～85%**。目前可以先实现差旅专属数据准备模块，统一产出 `serviceData.travelAudit`，接口缺失时按 fail-open 处理，不误拦截流程。

现有接口能够提供：

- 核销单、差旅行程、飞机、火车、酒店、市内交通、自驾车、补助、轮船/客车和差旅其他费用；
- 市内交通、自驾、补助、大交通、行李托运和其他费用的金额、日期、人员及行程基础信息；
- 月结/自购飞机、火车和市内交通的基础区分数据；
- 通用发票验真、黑名单、作废、红冲、重复使用和发票内容 OCR 数据。

当前不能稳定支持或文档未明确的字段主要是：含餐会议标识、行李重量、托运行李航司、表单进项税额、岗位字段实际返回、订单与发票稳定关联键，以及 `AuditTravel`/`FormInvoiceTaxView` 回写结构。

## 2. 已确认接口清单

| 数据组 | 方法 | 接口 | 用途 | 当前结论 |
|---|---|---|---|---|
| 核销单 | GET | `/audit/info/{instanceCode}` | 核销人、费用项目、申请金额、提交时间、岗位等 | 通用数据准备已调用，差旅模块复用 `auditInfo` |
| 业务费用明细 | GET | `/audit/bussness-fee-details/{instanceCode}` | 会议/培训、业务费用子项 | 可调用；含餐字段仍不足 |
| 差旅行程 | GET | `/audit/travel-journey-manage/{instanceCode}` | 起止时间、城市、天数、交通方式、标准、场站费用、自驾/住宿/补助概览 | 基本满足 |
| 飞机 | GET | `/audit/air-tickets/{instanceCode}` | 月结/自购机票、航班、时间、旅客、金额 | 基本满足，航司字段需确认 |
| 火车 | GET | `/audit/train-tickets/{instanceCode}` | 月结/自购火车票、车次、日期、旅客、席位、金额 | 基本满足 |
| 酒店 | GET | `/audit/hotels/{instanceCode}` | 月结/自购住宿订单 | 已覆盖，当前 32 个稽核点暂无直接酒店规则 |
| 市内交通 | GET | `/audit/city-transports/{instanceCode}` | 月结网约车、自购市内交通 | 基本满足 |
| 自驾车 | GET | `/audit/driving-cars/{instanceCode}` | 日期、金额、里程、标准、行程 ID | 基本满足 |
| 差旅补助 | GET | `/audit/travel-subsidies/{instanceCode}` | 天数、单日金额、总额、标准、城市 | 基本满足，含餐字段不足 |
| 其他大交通 | GET | `/audit/other-transports/{instanceCode}` | 轮船、客车票据 | 基本满足 |
| 差旅其他费用 | GET | `/audit/travel-other-expenses/{instanceCode}` | 行李托运、疫苗、网络电话卡、退改签 | 金额和日期基本满足，重量/航司不足 |

通用接口不在差旅模块重复封装：公司黑名单、公司清单、费用项目与票种、发票占用、发票文件、OCR、验真、作废、红冲等继续使用通用架构。

## 4. `serviceData.travelAudit` 数据契约

差旅数据准备统一输出：

```json
{
  "instanceCode": "核销单号",
  "employeeRole": "销售",
  "employeeRoleCode": "7",
  "verifiUserName": "核销人",
  "travelSegments": [],
  "cityStandards": [],
  "stationVehicleStandard": {},
  "expenseItems": [],
  "flightOrders": [],
  "trainOrders": [],
  "hotelOrders": [],
  "transportOrders": [],
  "selfDrivingMileage": [],
  "subsidyInfo": {},
  "baggageInfo": [],
  "taxInfo": {},
  "invoiceScene": null,
  "selfBoughtMonthlyTrain": null,
  "ruleStates": {},
  "sourceStatus": {},
  "primaryInvoice": true,
  "raisedRuleCodes": [],
  "messages": []
}
```

单据级数据放入收据上下文，当前发票 OCR 相关字段由发票级 enricher 合并，避免把不同发票的数据混在一起。

## 5. 当前实现策略

- 差旅接口客户端放在 `expense_audit_orchestrator/profiles/travel/client.py`；
- 差旅数据标准化放在 `expense_audit_orchestrator/profiles/travel/data.py`；
- profile 使用 `receipt_enrichers["travelAudit"]` 和 `invoice_enrichers["travelAudit"]`；
- 接口逐个调用、逐个降级；
- 外部接口缺失时保留 `sourceStatus` 和“差旅接口数据待接入，当前按通过处理”提示；
- 不复制通用 HTTP、认证和重试实现；
- 不修改通用图运行时和回写主流程；
- `TRAVEL_GRAPH_PATH` 未配置时默认使用 `graph-latest-travel-0807.json`。

## 6. 待后端确认事项

1. `/audit/info/{instanceCode}` 是否实际返回 `postTypeCode`、`postType`。
2. 是否增加会议/培训和含餐字段：
   - `isMeetingOrTraining`；
   - `meetingIncludesMeal`。
3. 行李接口是否补充：
   - `weight`；
   - `weightUnit`；
   - `airlineCode`；
   - `airlineName`；
   - `flightNo`；
   - `relatedFlightOrderId`。
4. 核销单或表单接口是否提供 `formInputTax`。
5. 行程、订单、费用、发票之间是否存在稳定的 `journeyid`、`expenseItemId`、`invoiceFileId`、`invoiceNo`、`relatedFlightOrderId`。
6. `tjmAirportreturncost` 是场站用车申报金额还是允许标准金额。
7. 提供真实 `AuditTravel` 和 `FormInvoiceTaxView` 回写样例。

## 7. 本报告的使用方式

后续接口联调时，以本报告的接口清单、字段缺口和 `travelAudit` 数据契约为基准。若接口字段发生变化，只更新差旅 profile 的客户端映射和标准化逻辑，不改流程图和通用回写架构。
